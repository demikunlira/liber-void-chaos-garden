# Validation and delivery

1. Preserve source and record tool versions, input hashes and changes. Use a new output directory for each revision.
2. Inspect layer registration and neutral composite against the approved reference. Use contrasting backgrounds, magnified seams and normal viewing size.
3. Exercise each input individually, then combinations: blink transitions, mouth form/open, head and body extrema and diagonals, hair roots and tips, poses, props and outfits. Inspect motion over time, reversal and settling, not just endpoints. Check hands, neck, hairline, torso and other affected regions.
4. For Live2D, check manifest references, textures and expressions; load the exact exported MOC in compatible licensed Cubism Core, and separately test Editor open/save/reopen if an editable project is promised. Run real target-app tracking, microphone and physics tests if available. A successful JSON parse, static image or numeric parameter change is not equivalent to visual or runtime success.
5. For VRM compare rig, expressions, metadata, materials and springs against the baseline, inspect affected poses and test in the target app. State actual tested scope and limitations.
6. Package editable source, runtime, dependencies that may legally be redistributed, build instructions, licenses, checksums, reports and previews. Verify the ZIP opens, references resolve, and its files match tested hashes. Identify external downloads and pending checks.
